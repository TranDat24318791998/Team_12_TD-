# [3.2] API trả dữ liệu mẫu

**Người làm:** TV3 · **Giờ:** 11:00–11:45 · **Cần có trước:** 1.2 (contracts/) · **Mở đường cho:** 3.3, 3.4

## Mục tiêu

Giao diện làm song song, không chờ agent. Đủ 9 API đúng hình dạng hợp đồng, trả dữ liệu từ `contracts/`, và mô phỏng được nhịp của buổi demo.

## Việc cần làm

1. `app/api.py`, router FastAPI gắn vào `app/main.py`, đủ 9 API ở `docs/CONTRACT.md` mục 3.
2. Khi `MOCK_API=1` (biến môi trường mới, mặc định 0):
   - Giữ một trạng thái giả trong bộ nhớ server, đi theo `step`: `idle` → `day/start` → `negotiating` → khi đã phát hết sự kiện mẫu → `awaiting_decision` → `decision` accept → `content_review` → `content/apply` → `day_done` → `night` → `night_done` và ngày tăng 1.
   - `GET /api/events?after=` phát dần sự kiện trong `contracts/events.json`: mỗi 1,2 giây kể từ `day/start` lộ thêm một sự kiện.
   - `content/retry`: tăng `version`, trả ảnh `running`; 5 giây sau `GET /api/state` trả ảnh `done` (đường dẫn ảnh giữ chỗ trong `static/img/placeholder-*.png`), video `running` thêm 15 giây rồi `done`.
   - `decision` với `negotiate` trả thẻ mẫu thứ hai (voucher 2%).
3. Khi `MOCK_API=0`: route gọi các hàm thật (task 3.5 làm); tạm thời trả 501 với `{"error": {"code": "not_ready"}}`.
4. Thêm `MOCK_API` vào `.env.example`.

## Output

`app/api.py`, sửa nhỏ `app/main.py`, `static/img/placeholder-*.png`, `tests/test_api_mock.py`.

## Tiêu chí xong

- Với `MOCK_API=1`, test bằng `TestClient` đi hết chuỗi reset → day/start → events (tua thời gian bằng cách giả đồng hồ) → decision → content/retry → content/apply → night → proof; mọi phản hồi hợp lệ với model trong `app/schemas.py`.
- `GET /api/events?after=3` chỉ trả sự kiện có `seq > 3`.
- Lỗi trả đúng dạng `{"error": {...}}`.
