# [2.2] Database: nhật ký sự kiện và store cho bộ nhớ

**Người làm:** TV2 · **Giờ:** 11:00–11:30 · **Cần có trước:** 1.2 · **Mở đường cho:** 1.5, 2.4, 3.2, 3.5

## Mục tiêu

Nhật ký sự kiện là nguồn sự thật: khung hậu trường đọc từ đây, học ban đêm đọc từ đây, bằng chứng tính từ đây. Khởi động lại server không mất dữ liệu đã chạy.

## Việc cần làm

1. `app/infrastructure/eventlog.py`, lớp `EventLog(db_path)` dùng `sqlite3`:
   - Bảng `events(run_id TEXT, seq INTEGER, day INTEGER, ts TEXT, type TEXT, actor TEXT, shop_id TEXT, text_vi TEXT, data TEXT, PRIMARY KEY(run_id, seq))`, chỉ mục theo `(run_id, day)`.
   - `add(run_id, day, type, actor, shop_id, text_vi, data) -> Event`: `seq` tăng dần trong một `run_id`, `ts` là giờ máy `HH:MM`, `data` lưu JSON (Pydantic model trong data được `model_dump`).
   - `since(run_id, after_seq) -> list[Event]`, `all(run_id, day=None, type=None) -> list[Event]`, `runs() -> list[str]`.
   - An toàn khi nhiều luồng ghi (một khoá, `check_same_thread=False`).
   - Kiểm tra `type` và `actor` thuộc danh sách ở CONTRACT mục 2; sai thì báo lỗi.
2. `app/infrastructure/store.py`:
   - `make_store(settings, path)` trả store của LangGraph: `InMemoryStore` cho test; bản lưu file (SqliteStore hoặc tương đương) cho demo nếu version LangGraph đã cài hỗ trợ. Kiểm tra tên module trong môi trường trước khi viết; không có thì dùng một store tự viết trên SQLite với cùng các hàm `put/get/search/delete` theo namespace.
   - Đường dẫn database: `runs/<run_id>/events.db` và `runs/<run_id>/memory.db`.

## Output

`app/infrastructure/eventlog.py`, `app/infrastructure/store.py`, `tests/unit/infrastructure/test_eventlog.py`.

## Tiêu chí xong

- Ghi 3 sự kiện → `since(run, 0)` trả đúng 3, `seq` là 1, 2, 3; `since(run, 2)` trả 1.
- 4 luồng cùng ghi 100 sự kiện → đủ 400, `seq` không trùng.
- Mở lại file database (đối tượng mới) vẫn đọc được sự kiện cũ.
- `type` không có trong danh sách → lỗi rõ ràng.
- Store: `put` rồi `get` trả đúng giá trị; tạo lại store từ cùng file vẫn còn (nếu dùng bản lưu file).
