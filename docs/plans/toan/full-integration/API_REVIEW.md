# HTTP API — Astra MAX review and implementation handoff

Reviewed 31 October 2026 at `33fbdd5`. Scope: HTTP composition, seller request/response contracts, scoped projection, asynchronous command visibility and proof delivery. Data/worker/media/Knowledge correctness belongs to the adjacent reviews. This file is the only output changed; no source, secrets, production DB, UI or paid providers were touched.

**Verdict: the existing Data HTTP application is the integration base.** The root app currently serves health/static files and empty business routers. Compose Data once at port 8000, attach the native in-process worker to its lifecycle, and keep experiment media at 8010 behind the backend. Do not implement another nine-route business runtime in `app/api`, call the core Session workflow alongside Data, or proxy the same business commands through a second HTTP server.

## 2. Composition and defaults

Implement in `app/main.py` by calling `data.growth_data.api.create_app` once with the configured Data home and content/learning defaults. Extend the Data factory with a small injectable bootstrap-defaults parameter, validated through its existing models; the standalone factory can retain reference defaults for explicit reference tests. Merge these defaults before the initial legacy create and reset. Do not change mode based on the mere presence of a browser request, and do not advertise live if the transport is offline.

Preserve Data's lifespan when adding the worker: wrap its existing lifespan context, recover Data before starting the worker, and stop/join the worker before service shutdown. Inject the worker factory for tests. No nested write connection or provider call belongs in startup recovery. `app/api` stubs should remain unused or be removed from composition; they must not receive copied business handlers. Preserve the simple root health response if current tests depend on it, but avoid registering two `/health` handlers with ambiguous order. Update its test intentionally if adding component status.

Mount public frontend files only after all API/internal routes and JSON 404 fallbacks. Generated business assets stay behind Data's scoped `/api/v1/runs/{r}/assets/{aid}/download`; do not expose the entire Data object tree or new private media through unauthenticated `StaticFiles`. The existing `/media/replay` public fixtures can remain for compatibility. Browser traffic stays same origin; no new CORS/auth framework is required. Media credentials, provider URLs and bearer tokens never enter browser payloads.

The integrated contract supersedes `DEMO_CONTRACT`'s old Session authority, sync-only start and two-day limit. Update that document together with frontend requirements, data requirements and shared fixtures during implementation. Existing nine route paths and direct JSON remain; `/api/v1` keeps its envelope. This is an agreed contract migration, not permission to revive the old parallel Session runtime.

## 3. Exact seller contract packet

Use `data/growth_data/models.py` for strict HTTP request DTOs, with `extra=forbid`, strict booleans and bounded strings. Do not create a competing schema set in `app/api/schemas.py`. These additions must ship with their frontend consumers and fixtures.

Keep UI `step='idle'` before/after confirmation and use `brief.confirmed` to select the action. This avoids adding `brief_confirmed` to every frontend enum/render path just to represent one predicate. The worker still requires an actual confirmed record. Confirmed brief persists across days; reset clears it. Public budget defaults null, not the private hard cap.

The job/content IDs above are identity checks, not browser-selected authority. Resolve all ownership and relations server-side: authenticated run/demo shop → approved card → proposal/brief → current content job/content → attempt. The canonical content version may exceed 3; never compare it to the attempt. Job version may advance during provider heartbeat, so ordinary approval checks the immutable draft binding/readiness, not an unrelated heartbeat version. Worker writes continue to use their own expected_job_version CAS.

Video review requires a real choice: ready bytes with review true can be included; review false/null requires explicit `video_review_ack=true`; unfinished/failed/missing bytes require `skip_video=true` to publish without video. Ack never overrides missing/corrupt bytes. Skip publishes `video=null` and late callbacks cannot attach it. The selected cover must always pass the media lane's file/size/hash and ownership gates. Persist cover, skip, ack and exact binding in the same approval receipt.

## 4. Operation, content and learning polling

Reuse `GET /api/v1/runs/{r}/operations/{oid}` and `GET /api/v1/runs/{r}/content-jobs/{jid}`; their responses are enveloped. For the nine-route React view, the existing state poll can supply both projections, so a duplicate seller job-poll route is unnecessary. Ensure state exposes actual current-job status/error/progress and sanitized slot metadata. v1 state currently queries jobs without ORDER BY; fix authoritative selection/order and callers/tests that use `jobs[-1]`, coordinated with DB/media owners.

`frontend/src/api.js` currently throws away 202 response metadata and `useRun.js` waits only for a changed step/card/attempt. Preserve operation identity/status on the pending result and wait for that operation or a documented committed target. A switch from content_review to another step alone must not claim the requested draft was published. A failed operation must not spend 70 seconds looking successful-but-slow. After timeout or lost response, GET the exact operation/current state and retry the same key/body only where its persisted outcome permits it. Unknown is visibly unresolved; it never authorizes a fresh paid operation/key.

Data's `active_operation` can cover reload recovery. Busy applies to start, renegotiation, close/learning and unresolved media where a conflicting mutation would discard the work. Guard at the Data transaction boundary as well as disabling UI. State/events remain readable while native/provider tasks are blocked on a test latch; no process-wide or session write lock across network IO.

Existing learning retry/skip endpoints are `/api/v1/runs/{r}/days/{day}/learning/{retry|skip}`, using `LearningControl` expected version and reason. Expose these only for an actual failed/pending handoff and honor DB/SI skip-versus-publication semantics. Skipping learning is distinct from skipping video. Do not auto-skip a failed night in a polling handler or turn an unknown reflection into permission to send another model invocation.

## 5. Event projection and scope

Retain Data's canonical `(run_id,seq)` authority. `service.events` already advances across hidden rows; preserve that behavior. Return its third value as `has_more`. Validate nonnegative integer `after` consistently with v1. Page until `has_more=false`, allowing an empty authorized page with an advancing cursor and rejecting a non-progressing cursor. Refresh polling and full export must not run independent competing cursor updates.

Map `agent_telemetry` to seller `agent_activity` in the facade, with the documented phase/status/negotiation/task/round/label. Derive the role from the trusted worker record/validated phase mapping, not a browser actor; add the same snapshot with committed updated_seq if the UI needs it. Preserve tool_called/tool_result/agent_completed as the agents lane's safe typed telemetry, including source and stable refs. Referee refs must be mapped from actual native turn IDs to this run/attempt's public Data event sequence.

Project card_sent as `{card}` from its immutable card/proposal/brief binding; include negotiation identity even when later resolved. Project seller_decision with card_id, native seller action, note_vi, rule_answer and version references; Data approve/request_changes are not the strings React displays. Project package_applied with exact approved package/card/negotiation/apply receipt. Map Shop counter distinctly from Data stance propose. No current-card lookup may reconstruct an old event after a new attempt exists. DB/SI reviews own missing persisted links and evidence, API owns the truthful serialization.

Preserve cookie HttpOnly/SameSite, same-origin write check, authenticated role/run/shop/job grants and existing scoped asset/download/export access. Require Idempotency-Key and X-Request-ID on all seller mutations, including reset, night and undo, with one consistent safe JSON error envelope. Same key/body replays its receipt; changed body conflicts before side effects. Body actor/shop/role cannot grant authority. Unknown API routes return JSON 404 and never static HTML. Invalid/foreign object IDs return controlled 404/409, not uncaught KeyError or raw sqlite/provider diagnostics.

A content worker scoped to a job must not obtain another job's content through convenience state/events endpoints. Seller proof/export must use the same permitted shop/run projection as state; `evidence.py` currently sums all shops' private contribution and wasted-ads calculations and needs a scoped metric projection. Do not relax scope because all local sample shops are simulated.

## 6. Proof delivery, without inventing evidence

Keep the existing comparison create/attach/read endpoints. The native SI runner creates ON/OFF runs with identical scenario, seed, seller policy and horizon, preserves independent memories, completes them, and attaches their real IDs to the seller session or grants the seller access. API composition must arrange that attachment; files generated under an unrelated service session will otherwise remain invisible to `/api/proof`.

API does not implement the experiment runner or invent winning metrics. It exposes the stored report and `comparison_days` following `FRONTEND_REQUIREMENTS` section 7: one common request identity/version per day, each branch's own event/proposal refs, earlier-day memory evidence, explicit source and outcome refs. Missing transcript/evidence remains unavailable. Never reuse preview SQLite fixtures as native proof. Keep null metrics visible with sample/window metadata instead of filtering them out in the legacy handler.

Return actual seed/horizon/profile/source from the selected pair; avoid the current hardcoded 42/seven-day not-ready placeholder. A persisted reference report must remain labeled reference and cannot satisfy the native learning evidence gate. GET proof is read-only. The preview-only `/api/demo/day7` and jump route are not missing production business APIs; dynamic preview requirements belong to the UI/data preview work and must remain clearly labeled samples.

Proof export should use `GET /api/v1/runs/{r}/events/export?format=jsonl`, which already freezes the upper cursor and filters through `service.events`, or explicitly drain all legacy pages. Frontend JSON-only `client.request` cannot parse JSONL; add a small authenticated raw download path in the client. No new export framework is needed.
